# SCM-ForecastX · 供应链需求预测与供应商风险驾驶舱

> 用 **Walmart M5 真实零售数据** 做需求预测，叠加 **参数化情景模拟的供应商风险层**，
> 输出可执行的补货与采购行动建议。

---

## 1. 一句话定位

把「预测 → 风险 → 建议」三段式做成一条**每个数字都能自洽解释**的供应链决策链：
预测侧以滚动原点回测 + 多基线对照取信，风险侧以透明规则评分 + 概率模拟替代黑箱打分，
决策侧把预测精度换算成安全库存与资金占用。

---

## 2. 业务问题

零售供应链计划员每周要回答三个递进的问题：

| 环节 | 业务问题 | 本项目输出 |
|---|---|---|
| ① 需求 | 未来 28 天每个 SKU 要多少货？ | 逐日预测 + 回测精度（WMAPE / MASE / Bias） |
| ② 供应 | 哪些供应商会掉链子、断供概率多大？ | QCDSM 评分 + 蒙特卡洛断供概率 + 风险等级 |
| ③ 决策 | 我这一周该做什么？ | 安全库存 / 再订货点 + Kraljic 分档 + 行动 SOP |

预测跨度 28 天，与 M5 官方评测口径一致，也贴近真实的月度计划节奏。

---

## 3. 数据来源与获取

### 3.1 需求侧：M5（真实数据）

M5 是 Walmart 公开的零售销量数据集，包含 3 个州、10 家门店、30,490 条
SKU-门店序列、1,941 天日销量，并附带日历（含节假日与 SNAP 补贴日）和
周度价格。它是需求预测领域公认的基准数据集。

需要 3 个文件：

```
data/raw/sales_train_evaluation.csv   (~122 MB)  日销量宽表
data/raw/calendar.csv                 (~103 KB)  日期 / 星期 / 节假日 / SNAP
data/raw/sell_prices.csv              (~203 MB)  周度价格
```

**获取方式 A（推荐，无需 Kaggle 账号）**——公开镜像数据集：

```bash
# 销量表
curl -L -o m5_sales.zip \
  "https://www.kaggle.com/api/v1/datasets/download/bassemyasser205/m5-sales-train-evaluation-csv"
# 日历 + 价格（含销量，取其中 calendar.csv 与 sell_prices.csv 即可）
curl -L -o m5_full.zip \
  "https://www.kaggle.com/api/v1/datasets/download/dilshad200/m5-forecasting-accuracy"
```

解压后把三个 CSV 放进 `data/raw/`。实测下载速度约 2 MB/s。

**获取方式 B**——官方比赛页（需免费注册 Kaggle 账号并接受比赛规则）：
<https://www.kaggle.com/competitions/m5-forecasting-accuracy/data>

> 数据文件体积较大，已在 `.gitignore` 中排除，不进版本库。

### 3.2 供应侧：为什么是「模拟」的

**M5 只有零售 POS 数据，不含供应商信息。** 企业采购主数据（供应商名录、真实
交期、质量记录、价格协议）属于商业敏感数据，任何公开数据集都不提供。

因此本项目采用**参数化情景模拟**：

- 每一项分布参数都在 `config.py` 中显式声明，随机种子固定（`RANDOM_SEED=42`），
  结果可复现；
- 参数取值锚定行业公开区间与专家先验（如快消品跨境交期 20–45 天、
  准时交付率 0.85–0.98、变异系数 0.29），在代码注释中逐条说明依据；
- 输出表的**列名对齐采购主数据字段**（`supplier_id / lead_time_days / otd_rate /
  dppm / price_index / ...`），可直接替换为 ERP/SRM 导出表。

> 设计取舍：需求侧用真实数据，供应侧因公开数据集不提供采购主数据，
> 做成透明、可复现的情景模拟，并把接口设计成可直连 SRM 导出表。

## 5. 方法论设计

预测类项目最常见的失败不是「跑不起来」，而是「跑起来但数字不可信」。
以下七条设计原则逐条针对一类常见错误：

| # | 常见错误 | 本项目做法 |
|---|---|---|
| 1 | 按行号切分（序列按 SKU 拼接时，切出的是 SKU 子集而非时间窗口，训练与验证日期完全重叠） | **按预测原点切分**：训练目标严格早于验证窗口，`tests/test_no_leakage.py` 用断言钉死 |
| 2 | 风险标签与特征同源（用特征加权造标签，再用同组特征训练分类器，准确率只是背公式） | **拆成规则评分（QCDSM）+ 概率模拟（蒙特卡洛）**，不训练风险分类器 |
| 3 | 无 baseline 对照，无法证明模型有价值 | 固定跑 7 个 baseline（末值 / 季节性 naive / 28 日均值 / drift / Holt / Croston / SBA），报告 **MASE**（<1 才算赢） |
| 4 | 只有 MAE/RMSE，对零销量序列分母失真 | **WMAPE**（销量加权）+ **MASE**（可跨序列比较）+ **Bias%**（暴露系统性偏差） |
| 5 | 指标口径混用（原始单位与归一化值并排，量级不可比） | 所有指标在**同一口径**下对照，单位与缩放方式在文档中写死 |
| 6 | 伪造库存（预测均值 × 常数充当在手库存） | **不伪造库存**：输出目标库存水位，并说明真实落地需对接 WMS 在手库存 |
| 7 | 用 LLM 转述数字（生成式模型会把数值关系说反） | **叙述层模板化**，数字全部来自确定性计算引擎 |

python -m venv .venv && .venv/Scripts/activate      # Windows
pip install -r requirements.txt

## 7. 关键结果（CA_1 / FOODS_3，823 条序列，3 折 × 28 天滚动回测）

**需求侧**

| 模型 | WMAPE | MAE | RMSE | MASE | Bias% |
|---|---|---|---|---|---|
| 末值外推（naive） | 0.8900 | 2.402 | 4.772 | 1.223 | **+26.8** |
| 季节性 naive | 0.7278 | 1.965 | 3.818 | 1.000 | −4.2 |
| 28 日均值 | 0.6297 | 1.700 | 3.295 | 0.865 | −4.5 |
| 线性漂移（drift） | 1.1898 | 3.211 | 6.716 | 1.635 | +58.4 |
| Holt 双参数平滑 | 0.9167 | 2.474 | 4.871 | 1.260 | +25.0 |
| Croston（间歇专用） | 0.6888 | 1.859 | 3.499 | 0.946 | +4.0 |
| SBA（Croston 修正） | 0.6781 | 1.830 | 3.465 | 0.932 | −1.2 |
| **LightGBM（Tweedie）** | **0.6038** | **1.630** | **3.112** | **0.830** | **−1.3** |

结果解读：

1. **MASE = 0.83 < 1，模型赢过全部 7 个基线**——包括教科书级的间歇需求方法
   （Croston 0.946 / SBA 0.932），WMAPE 比季节性 naive 低 12.4 个百分点。
2. **但 28 日均值这个 baseline 相当强**（MASE 0.865，只比模型差 4%）。
   原因是本切片有 53% 的日销量为 0，属于典型的间歇性需求，简单移动平均已能
   吃到大头；模型的边际价值不在点预测精度，而在 **Bias 从 −4.5% 收敛到 −1.3%**
   以及不确定性刻画。
3. **趋势类方法在间歇需求上系统性失灵**：drift（MASE 1.635）和 holt（1.260）
   反而比 naive 还差——零销量放大数据噪声，线性外推会「追噪声」。
   方法的价值取决于需求形态，而不是复杂度。
4. **日均粒度的 WMAPE 天然偏高**。真实计划按周、按品类评审，聚合后误差会显著
   下降；本项目保留日粒度是为了让回测更严格。

**供应侧**（参数化情景模拟）

| 指标 | 数值 |
|---|---|
| 供应商家数 / SKU-供应商关系 | 120 家 / 1,261 条 |
| 单源 SKU | 385 条（占 31%） |
| 供应商集中度 HHI | 0.0245（最大供应商占采购额 5.7%） |
| 风险等级分布 | 高 655 / 中 436 / 低 138 / 极高 32 |
| 平均断供概率（现行「交期 + 7 天」口径） | 16.7% |
| 高风险及以上涉及采购金额 | 43.7% |

**库存与决策**

| 指标 | 数值 |
|---|---|
| 目标服务水平 / 安全系数 | 95% / Z = 1.645 |
| 平均安全库存 / 平均再订货点 | 34.3 件 / 95.5 件 |
| ABC×XYZ 分布 | X 89 / Y 184 / Z 550 |
| Kraljic 分布 | 常规 492 / 瓶颈 391 / 杠杆 264 / 战略 114 |

**服务水平 ↔ 库存资金权衡**（`src/sensitivity.py`，相对 95% 基准）：

| 目标服务水平 | Z | 安全库存（件） | 安全库存资金 | 相对 95% | MC 验证达成 |
|---|---|---|---|---|---|
| 90% | 1.282 | 33,658 | $84,244 | −22.1% | 89.5% |
| 95% | 1.645 | 43,188 | $108,097 | 基准 | 93.7% |
| 97.5% | 1.960 | 51,458 | $128,797 | +19.1% | 96.1% |
| 98% | 2.054 | 53,926 | $134,974 | +24.9% | 96.6% |
| 99% | 2.326 | 61,067 | $152,848 | +41.4% | 97.8% |

两个结论：① 服务水平的提升是**非线性变贵**的——97.5% 到 99% 只差 1.5 个百分点，
库存资金却要多压 19%（$128,797 → $152,848），"保供 vs 成本"必须显式权衡；
② 蒙特卡洛验证显示正态近似在高服务水平段**系统性高估**达成率（目标 99%，实际
约 97.8%）——间歇性需求的右偏分布使安全系数 Z 法偏乐观，这是解析公式的已知边界，
也是保留 MC 验证的原因。

**把精度翻译成钱**：相较季节性 naive，模型使平均残差标准差 σ_d 下降 **22.8%**，
在同服务水平下安全库存下降 **9.8%**。

## 8. 诚实边界

1. **供应侧数据是模拟的**，见 3.2。所有结论只用于演示方法与流程，不代表任何
   真实企业的供应风险状况。
2. **不含在手库存**，因此输出的是目标水位而非补货量。
3. **不含订单与在途**，未做 MRP 展开与产能约束。
4. **成本参数为量纲演示**（`annual_spend` 由销量乘价格区间生成），非真实财务数据。
5. **蒙特卡洛是需求与交期的不确定性近似**（随机游走近似累计需求），
   未引入相关性结构与供应中断的跳跃项。

## 9. 常见问题（FAQ）

**Q：为什么不直接用 Kaggle 官方数据？**
A：M5 需要接受比赛规则才能下载，本项目用的是公开镜像的同一份数据（行数 30,490 ×
1,941 天可与官方核对一致）。数据本身完全相同，差别只是获取通道。

**Q：供应商数据是模拟的，这个项目还有什么意义？**
A：需求侧 100% 真实，是项目的价值主体；供应侧因公开数据集不提供采购主数据，
所以做成透明、可复现的情景模拟，并把接口对齐 SRM 导出字段。关键在于明确
哪些指标该用真实数据算、哪些必须标注为模拟。

**Q：为什么用 WMAPE 而不是 MAPE 或 RMSE？**
A：M5 有 53% 的日销量为 0，MAPE 的分母会在零值处爆炸；RMSE 会被大销量 SKU
主导。WMAPE 用总销量做权重，是零售计划的通行口径。同时保留 MASE 用于
「是否赢过朴素方法」的判定，Bias 用于发现系统性高估。

**Q：安全库存的公式为什么这么写？**
A：`SS = Z·√(L·σ_d² + d̄²·σ_L²)`，同时考虑需求波动（σ_d，取自回测残差）与
交期波动（σ_L）。只用需求波动会低估风险——交期的方差同样会传导成缺货。
这样写还有一个好处：预测精度提升会直接体现为 σ_d 下降，安全库存随之下降，
把「模型指标」翻译成了「资金占用」。

**Q：你怎么证明没有用未来信息？**
A：有一个可执行的测试（`tests/test_no_leakage.py::test_features_ignore_future`）：
把预测原点之后的真实数据整体随机打乱，重新构造特征，断言特征矩阵一字不变。
这个测试专门用来捕捉「h > 7 时用了 t−7」这类隐蔽泄漏。
