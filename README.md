# forecast-driven-replenishment

用沃尔玛 M5 真实零售数据做需求预测，把预测结果落成可执行的补货策略：每个 SKU 备多少安全库存、什么时候下补货单、哪些供应商关系需要优先处理。预测精度最终换算成库存资金占用 —— 这是它对业务的实际意义，模型指标本身不是目的。

## 业务问题

零售补货计划里，预测和下单是两件常被混为一谈的事。预测回答"未来 28 天每个 SKU 卖多少"，下单要在此基础上叠加交期、供应商可靠性、服务水平目标，算出再订货点和安全库存。多数预测项目停在前半段；这个项目把后半段也做了，并让两段之间的传导关系可以追溯：

- 预测误差（σ_d）直接进入安全库存公式，模型每改善一分，资金占用就少一分；
- 供应商风险用 QCDSM 规则评分加蒙特卡洛模拟，不用特征加权造标签再训练分类器 —— 那类做法的准确率只是在拟合造标签的公式；
- 一个 SKU 可挂多家供应商（主供 + 备供，带份额），双源对断供风险的抑制效果被直接量化出来。

## 数据

需求侧是 M5（Walmart 公开零售数据集）：30,490 条 SKU-门店序列 × 1,941 天日销量，附带日历（节假日、SNAP 补贴日）和周度价格。默认范围取 CA_1 门店的 FOODS_3 品类，共 823 条序列，53% 的日销量为 0 —— 典型的间歇性需求，这个特征决定了后面的方法选择。

```
data/raw/sales_train_evaluation.csv   (~122 MB)  日销量宽表
data/raw/calendar.csv                 (~103 KB)  日期 / 星期 / 节假日 / SNAP
data/raw/sell_prices.csv              (~203 MB)  周度价格
```

三个文件可从 Kaggle 公开镜像免账号下载（命令见下），数据与官方比赛页完全一致。

供应侧没有公开数据可用 —— 供应商交期、质量记录、价格协议属于企业的商业敏感数据，任何公开数据集都不提供。这一层用参数化情景模拟：分布参数在 `config.py` 里显式声明、随机种子固定，取值锚定行业公开区间（跨境交期 20-45 天、OTD 0.85-0.98、交期变异系数 0.29），输出表的列名对齐 SRM 导出字段，拿到真实采购主数据后可直接替换。

## 方法

### 需求预测（`src/forecast.py`）

滚动原点回测：3 折 × 28 天，训练目标严格早于验证窗口。所有滞后与滚动统计都以预测原点为右端点，季节性滞后取"原点及以前最后一个同星期值"而不是固定的 t-7 —— 后者在预测期超过 7 天时就是未来信息。

评估固定跑 7 个基线：末值外推、季节性 naive、28 日均值、drift、Holt、Croston、SBA。没有基线对照的预测结果无法证明价值；Croston 和 SBA 是间歇性需求的经典专用方法，赢过它们才有说服力。

主模型是 LightGBM（Tweedie 损失，variance_power=1.1）。选 Tweedie 是因为 53% 零销量的计数型需求既不适合 MAE/MSE（忽略零值结构）也不适合 Poisson（方差强制等于均值）；选树模型而不是深度学习，是因为 160 万样本的规模下树模型更稳、更快、特征重要性可以直接给业务方看。

指标用 WMAPE（规避零销量分母）、MASE（以季节性 naive 为标尺，跨序列可比）、Bias%（暴露系统性偏差）。

### 供应商风险（`src/risk.py`）

供应商是实体，不是 SKU 的附属属性：先建 120 家供应商主表（每家一套 OTD / DPPM / 交期 / 财务健康度），再生成 1,261 条供货关系，一家供应商服务多个 SKU。若每个 SKU 各配一个独立"供应商"，集中度指标（HHI）就失去意义了。

评分与概率分开做：QCDSM 五维加权（Delivery 0.30 / Quality 0.20 / Cost 0.20 / Service 0.15 / Management 0.15）是透明的规则，不学习；断供概率是蒙特卡洛模拟交期与需求的联合波动，也不学习。两者不构成循环。

一个 SKU 挂多家供应商时（A/B 类双源，主供份额 65%~85%），SKU 级断供概率取主备联合概率。备供保持小份额持续下单是采购实务的通行做法 —— 备供长期没有订单，产能响应和商务关系都会退化，真到切换时接不住。

### 库存策略（`src/plan.py`）

安全库存同时考虑需求波动和交期波动：

```
SS = Z · sqrt(L·σ_d² + d̄²·σ_L²)
```

只用需求波动的简化式会低估风险，交期的方差同样会传导成缺货。σ_d 取回测残差的标准差 —— 预测模型的实测误差，不是历史销量的波动。这让预测精度直接连通资金占用：模型使 σ_d 下降 22.8%，同服务水平下安全库存下降 9.8%。

双源 SKU 的每条供货关系按份额口径计算水位：向主供下单覆盖 75% 的需求，就按 75% 的口径备安全库存和再订货点。

分类分档用三个正交维度：ABC（采购金额）、XYZ（需求变异系数，Syntetos 口径）、Kraljic（支出 × 供应风险）。每格对应差异化的行动 SOP，而不是一刀切。

### 叙述层（`src/narrative.py`）

决策建议的数字全部来自确定性计算引擎，叙述层只做模板填充和排序。不用生成式模型转述数字 —— 数值关系被改写的风险不值得冒。

## 结果

**需求侧**（823 序列，3 折 × 28 天滚动回测）：

| 模型 | WMAPE | MASE | Bias% |
|---|---|---|---|
| 末值外推 | 0.890 | 1.223 | +26.8 |
| 季节性 naive | 0.728 | 1.000 | −4.2 |
| 28 日均值 | 0.630 | 0.865 | −4.5 |
| drift | 1.190 | 1.635 | +58.4 |
| Holt | 0.917 | 1.260 | +25.0 |
| Croston | 0.689 | 0.946 | +4.0 |
| SBA | 0.678 | 0.932 | −1.2 |
| LightGBM（Tweedie） | **0.604** | **0.830** | **−1.3** |

三点值得注意：

1. 28 日均值是个沉默的强对手（MASE 0.865，只比模型差 4%）—— 间歇性需求下简单移动平均已经吃掉大部分信号，模型的边际价值在 Bias 从 −4.5% 收敛到 −1.3%，以及不确定性刻画（σ_d 下降 → 安全库存下降）。
2. drift 和 Holt 比 naive 还差。零销量放大数据噪声，线性外推在追噪声。方法的价值取决于需求形态，不是复杂度。
3. 日均粒度的 WMAPE 天然偏高（0.6~0.9）。真实计划按周、按品类评审，聚合后误差会显著下降；保留日粒度是为了让回测更严格。

**供应侧**（参数化情景模拟）：

| 指标 | 数值 |
|---|---|
| 供应商 / 供货关系 | 120 家 / 1,261 条 |
| 单源 / 双源 SKU | 385 / 438（A/B 类双源，主供份额 65%~85%） |
| 单源 SKU 平均断供概率 | 19.8% |
| 双源 SKU 联合断供概率 | 2.5% |
| 供应商集中度 HHI | 0.0243（最大供应商占采购额 6.5%） |

**库存与决策**：

| 指标 | 数值 |
|---|---|
| 目标服务水平 / Z | 95% / 1.645 |
| 平均安全库存 / 再订货点 | 18.8 件 / 51.8 件 |
| Kraljic 分布 | 常规 483 / 瓶颈 399 / 杠杆 273 / 战略 106 |
| XYZ 分布 | X 32 / Y 115 / Z 676 |

**服务水平 ↔ 库存资金**（`src/sensitivity.py`，相对 95% 基准）：

| 目标服务水平 | 安全库存资金 | 相对 95% | MC 验证达成 |
|---|---|---|---|
| 90% | $47,713 | −22.1% | 89.5% |
| 95% | $61,223 | 基准 | 93.7% |
| 97.5% | $72,946 | +19.1% | 96.1% |
| 98% | $76,445 | +24.9% | 96.6% |
| 99% | $86,568 | +41.4% | 97.8% |

服务水平的提升非线性变贵：97.5% 到 99% 只差 1.5 个百分点，库存资金要多压 19%。蒙特卡洛验证还显示正态近似在高服务水平段系统性高估达成率（目标 99%，实际约 97.8%）—— 间歇性需求的右偏分布使 Z 法偏乐观，这是解析公式的已知边界，也是保留 MC 验证的原因。

## 运行

```bash
# Python 3.11 / 3.12（numpy 1.26 无 3.13 轮子）
python -m venv .venv && .venv/Scripts/activate
pip install -r requirements.txt

# 下载 M5 数据（免 Kaggle 账号，约 2 MB/s）
curl -L -o m5_sales.zip \
  "https://www.kaggle.com/api/v1/datasets/download/bassemyasser205/m5-sales-train-evaluation-csv"
curl -L -o m5_full.zip \
  "https://www.kaggle.com/api/v1/datasets/download/dilshad200/m5-forecasting-accuracy"
# 解压后把三个 CSV 放进 data/raw/

python run_all.py              # 全流程（回测约数分钟）
streamlit run dashboard/app.py  # 看板
pytest tests/ -v               # 含 4 项防泄漏断言
```

范围在 `config.py` 里调：`STORE = None` 扩到加州全部门店（3,292 条序列）。数据文件也可用环境变量 `M5_RAW_DIR` 指到仓库外。

防泄漏测试值得单独一提：`test_features_ignore_future` 把预测原点之后的真实数据整体随机打乱、重新构造特征，断言特征矩阵一字不变 —— 任何 lag 型泄漏都会让这个测试红。

## 假设与边界

1. 供应侧是参数化模拟，结论只演示方法与流程，不代表真实企业的供应风险；接口已对齐 SRM 字段，可替换为真实数据。
2. M5 是 POS 数据，不含在手库存 —— 输出的是目标库存水位，不是补货量；落地需对接 WMS 做差额。
3. 不含订单与在途，未做 MRP 展开与产能约束。
4. 双源联合断供概率按主备独立近似。同区域供应商的风险实际正相关（同一地缘事件同时冲击主备），独立假设低估联合概率 —— 主备跨区域配对是缓解方向。
5. 蒙特卡洛用随机游走近似累计需求，未引入相关性结构与供应中断的跳跃项。

## 后续方向

- 主备跨区域配对作为双源策略的显式约束（降低联合概率被低估的部分）
- 补货量（order quantity）而不只是水位：引入 EOQ 或 (s, Q) 策略的批量维度
- 按周的聚合口径回测，与 S&OP 月度评审节奏对齐
